Analytics handover — donation tax calculator

What the Media Agency has to add to their Google Tag Manager container, and what we do on the widget side.

The Fred Hollows Foundation (HK) · tax calculator embed · 24 Nov 2026 · 2SK Solutions
Container: GTM-M7QJ9DZK  ·  replaces: GTM-P3Q6PF55 on the campaign page

The short version. The calculator runs inside an iframe, and it never loads a tag manager of its own — by design, so it can be embedded anywhere without shipping a second container onto the Foundation's page. It reports what a donor does by postMessage to the parent page. Your container needs one Custom HTML tag to catch those messages and push them into the data layer, plus the usual GA4 tag, trigger and variables. Nothing on our side changes.
Checked on the live page, 24 Nov 2026. The campaign page currently loads GTM-P3Q6PF55 only, and that container carries no bridge — a synthetic widget message produced no data layer push. So there is nothing to un-pick: when GTM-M7QJ9DZK replaces it, there will be one container and one bridge. No duplicate events, no cleanup of old tags required.

2 · How the widget talks to the page

Every event arrives on the parent page as a message with this shape:

{ type: "event", name: "calc_started", source: "fhf-taxcalc", v: "1.x", lang: "en",
  params: { … } }

Three rules for whatever reads it:

  • Filter on source === "fhf-taxcalc". Other scripts on the page post their own messages.
  • Ignore every message where type !== "event" — the same channel also carries resize and deeplink messages, which are plumbing, not analytics.
  • The widget never sets page_location for you; take the page URL from the container's own page context.

3 · The custom code — the bridge

Tag: FHF — widget bridge · Type: Custom HTML · Trigger: All Pages

<script>
window.dataLayer = window.dataLayer || [];
window.addEventListener("message", function (e) {
  var d = e.data;
  if (!d || d.source !== "fhf-taxcalc") return;   // not our widget
  if (d.type !== "event") return;                  // resize / deeplink are plumbing
  var payload = Object.assign({}, d.params || {});
  payload.event = d.name;                          // dataLayer "event" drives the trigger
  payload.widget_lang = d.lang || "";              // prefixed so it cannot clash in a shared container
  delete payload.lang;                             // same value, sent once
  dataLayer.push(payload);
});
</script>
Do not add this tag to the iframe. It has to run on hollows.org, in the parent page — a tag inside the iframe cannot see the parent's data layer, and the widget deliberately ships no container.

5 · Trigger

Trigger: CE — FHF widget events · Type: Custom Event · Event name: matches RegEx

^(calc_started|calc_result_shown|qr_view|rail_click|email_capture|receipt_request|receipt_fulfilled|donation_self_report)$

One trigger covers every event. The last two are not live yet — they are reserved for the receipt system and land when that phase ships, so the trigger does not have to be edited later.

6 · GA4 tags

  • GA4 — config · Google Tag · Measurement ID G-… · Trigger Initialization – All Pages.
  • GA4 — FHF widget event · GA4 Event · Event Name {{Event}} · Trigger CE — FHF widget events · Parameters: band → {{DLV - band}}, donation_type → {{DLV - donation_type}}, rail → {{DLV - rail}}, state → {{DLV - state}}, cap_state → {{DLV - cap_state}}, widget_lang → {{DLV - widget_lang}}.

{{Event}} is a built-in variable. Do not create a data layer variable called Event — that is the most common way this setup fails silently.

8 · Verify before publishing

  1. Open the campaign page in GTM Preview.
  2. Type an amount into the calculator. Two events must appear: calc_started, then calc_result_shown.
  3. Open either event and read its parameters. There must be no amount, no income, no tax rate — only coarse bands and states. That is a deliberate constraint of the build: the widget cannot report a donor's finances. If you see a figure, stop and tell us.
  4. Scroll the payment block fully into view: qr_view. Click the AlipayHK tile: rail_click carrying rail.
  5. GA4 → Admin → DebugView — same events, same parameters, within a minute of publishing.

Appendix · the embed itself

The campaign page hosts the calculator in one iframe. It needs no tag manager and takes no parameters — but it does need the right height, or the bottom of the block is clipped on small phones.

<iframe src="https://2skdigitals.github.io/fhf-taxcalc-poc/embed/?lang=en"
        width="100%" height=2550 frameborder=0></iframe>
  • ?lang=en for the English page, ?lang=zh for the Chinese one. Everything else is automatic.
  • Write the height as a bare integer. height=2,550 parses as 3 in every browser — a thousands separator silently collapses the frame and the calculator disappears.
  • The page currently carries height=2200. Measured content is 2,162 at desktop and 2,202 at 390px, so it fits until a 320px-wide phone, where the block is 2,482 and roughly 280px is cut off.
