Analytics handover — donation tax calculator

The calculator's container runs inside the iframe. This is what to build in GTM-M7QJ9DZK, and how to debug a container that is not on the page.

The Fred Hollows Foundation (HK) · tax calculator embed · 24 Nov 2026 · 2SK Solutions
Container: GTM-M7QJ9DZK, loaded by the calculator frame  ·  Page: hollows.org campaign page

How it works now. The calculator is embedded in an iframe. That frame loads GTM-M7QJ9DZK itself and pushes every interaction into its own data layer — so no bridge tag and no custom code are needed anywhere. Your work is entirely on the GA4 side: one config tag, one event tag, one trigger, some variables, and the custom dimensions.
Two things before you build. Everything published in this container runs inside the Foundation's calculator frame, so keep it to GA4 tags — no Custom HTML tags in this container. And the container id is compiled into the widget by us, not taken from a URL: if it ever changes, tell us and we redeploy.

2 · What the frame sends to your container

For each interaction the calculator pushes one object into the data layer inside the iframe:

{ event: "calc_result_shown",
  band: "band", donation_type: "once", cap_state: "unlikely", exact: "no",
  widget_lang: "en",
  page_location: "https://www.hollows.org/en-HK/campaigns/charitable-tax-deduction/" }

Two fields need your attention:

  • page_location is the campaign page, not the frame. We set it deliberately — otherwise GA4 files the calculator as its own website (2skdigitals.github.io) and the session splits from the page that earned the traffic. Your config tag must use it, or it is ignored (see §3.3).
  • widget_lang is en or zh, so the two builds can be split.

No amount, income figure or tax rate is ever sent. That is a constraint of the build, not an oversight — if one ever appears, treat it as a defect and tell us.

3.2 · Trigger

Custom Event · event name matches RegEx:

^(calc_started|calc_result_shown|qr_view|rail_click|email_capture|receipt_request|receipt_fulfilled|donation_self_report)$

Four of these fire today. email_capture and receipt_request are dormant until the receipt module ships, and the last two are reserved — the regex covers all eight so the trigger never needs editing.

3.3 · GA4 configuration tag

  • Google Tag · Measurement ID G-… · Trigger Initialization – All Pages.
  • Fields to set → page_location = {{DLV - page_location}}. This is the line that keeps the calculator on the campaign page in your reports. Without it, every hit lands on 2skdigitals.github.io.

3.4 · GA4 event tag

  • GA4 Event · Event Name {{Event}} · Trigger from §3.2.
  • Parameters: band, donation_type, rail, state, cap_state, widget_lang — each mapped to its data layer variable.

{{Event}} is a built-in variable. Do not create a data layer variable called Event — that is the most common way this setup fails silently.

5 · Debugging a container that is not on the page

GTM Preview attaches to the page you open, so opening the campaign page will show you nothing — the container is inside the frame. Instead:

  1. Open the calculator frame directly in a tab: https://2skdigitals.github.io/fhf-taxcalc-poc/embed/?part=all&lang=en
  2. Attach Preview to that URL. Tags fire there exactly as they do on the live page.
  3. Type an amount. Expect calc_started, then calc_result_shown.
  4. Check the parameters carry page_location (the campaign page) and widget_lang.
  5. GA4 → Admin → DebugView: the same events, within a minute of publishing.
Consent. A container inside a cross-origin frame is not governed by the page's consent banner. We can either load it on first paint or hold it until the page signals consent — tell us which, and the Foundation's legal position should decide it rather than the tag setup.

Appendix · the embed itself

The container id is compiled into the widget, so the embed takes no parameter for it. The frame only needs the right height.

<iframe src="https://2skdigitals.github.io/fhf-taxcalc-poc/embed/?lang=en"
        width="100%" height=2550 frameborder=0></iframe>
  • ?lang=en on the English page, ?lang=zh on the Chinese one.
  • Write the height as a bare integer. height=2,550 parses as 3 in every browser and the calculator vanishes.
  • The page currently carries height=2200: measured content is 2,162 at desktop and 2,202 at 390px — it fits until a 320px-wide phone, where the block is 2,482 and roughly 280px is cut off.
